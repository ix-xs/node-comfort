This guide teaches you **node-comfort**, from installation to a program that
runs on a server. Each step tells you **what to do** and **why**.

## What node-comfort is

Almost every Node.js project ends up installing the same tools: a logger,
dotenv, a validation library, an HTTP client, a retry helper, a date library,
a CLI toolkit. node-comfort puts them in **one package with no
dependencies**, built only on what Node.js ships: `fetch`, `Intl`,
`node:crypto`, `node:sqlite`.

```js
const nc = require("@ix-xs/node-comfort");

const config = nc.env.validate({ PORT: { type: "port", default: 3000 } });
const users = nc.readJSON("data/users.json", []);
nc.success(`Loaded ${users.length} users, port ${config.PORT}`);
```

| Why | What it means for you |
| --- | --- |
| One dependency instead of twenty | One version to follow, one changelog to read. Nothing runs at install time. |
| One way of doing things | Durations are `"5m"` or milliseconds, options come last, errors carry a stable `code`. |
| Documentation in your editor | Every function, option and type is described, in JavaScript as in TypeScript. |
| Fast to load | About 4 ms. Each namespace loads the first time you use it. |

## What is inside

| Namespace | What it does |
| --- | --- |
| [`logger`](/essentials/logger/) | Logs with levels, colors, JSON output and log files |
| [`fs`](/essentials/fs/) | Files and folders: atomic writes, JSON, glob, watch |
| [`env`](/essentials/env/) | `.env` loading and a typed, checked configuration |
| [`checker`](/essentials/checker/) | Type checks and validators that are also TypeScript type guards |
| [`schema`](/data/schema/) | Validation, with the TypeScript type inferred for you |
| [`str`](/data/str/), [`num`](/data/num/), [`arr`](/data/arr/), [`obj`](/data/obj/) | Everyday helpers for strings, numbers, arrays and objects |
| [`time`](/data/time/) | Dates in any language and time zone, durations, schedules |
| [`id`](/data/id/), [`crypto`](/system/crypto/) | Ids, tokens, password hashing, encryption, JWT, 2FA codes |
| [`async`](/flow/async/), [`func`](/flow/func/) | Concurrency limits, queues, retry, debounce, memoize |
| [`Cache`](/flow/cache/), [`Emitter`](/flow/emitter/) | An LRU cache and a typed event emitter |
| [`http`](/system/http/) | A `fetch` client with JSON, retries, timeouts and hooks |
| [`SQLite`](/system/sqlite/) | The database built into Node.js, with filters and migrations |
| [`cli`](/system/cli/), [`color`](/system/color/), [`sys`](/system/sys/) | Arguments, prompts, spinners, tables, colors, processes |

## What you should know first

- **The basics of JavaScript**: functions, objects, `require`, `async` and
  `await`.
- **How to open a terminal** in a folder and type a command there.

You don't need TypeScript. The guide uses CommonJS, the default of Node.js;
[Installation](/start/installation/#commonjs-es-modules-and-typescript) shows
the same code in ES modules and TypeScript.

## How to read this guide

- A code block with a **file name** is a file to create, or to replace, at
  that place in the project. Highlighted lines are the new ones.
- A terminal shows what the code of the page prints. It ran when this site was
  built, so the output is real. **Replay** runs the scene again.
- **Next**, at the bottom of the page, takes you to the following step.
