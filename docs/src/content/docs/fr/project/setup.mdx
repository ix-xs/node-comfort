Au fil des sept pages qui suivent, vous construisez **status**, un petit outil
qui vérifie que vos sites répondent, garde un historique, et tourne tout seul
sur un serveur. Cette page crée le projet et son premier script.

## Créer le dossier

```bash
mkdir status
cd status
npm init -y
npm install @ix-xs/node-comfort
```

`npm init -y` écrit `package.json`, qui décrit le projet. `npm install` y
ajoute node-comfort, ainsi que dans `node_modules/`.

## Écrire le premier script

```js title="status.js"
const nc = require("@ix-xs/node-comfort");

nc.info("Starting the status check");
nc.success("node-comfort works");
nc.warn("There is no site to check yet");
```

Le programme raconte ce qu'il fait grâce au logger, que vous utiliserez à
chaque page. Il ne demande aucune préparation :

| Appel | Badge | Va vers |
| --- | --- | --- |
| `nc.info()` | `ℹ INFO` | stdout |
| `nc.success()` | `✔ OK` | stdout |
| `nc.warn()` | `⚠ WARN` | stderr |
| `nc.error()` | `✖ ERROR` | stderr |

- **Pourquoi l'heure :** quand le programme tourne des heures, vous savez quand
  chaque ligne est arrivée.
- **Pourquoi deux sorties :** les avertissements et les erreurs vont sur
  stderr, si bien que `node status.js > out.txt` les laisse à l'écran.
- **Pourquoi pas de couleurs dans un fichier :** les couleurs sont pour un
  terminal. Redirigées vers un fichier, les mêmes lignes sont du texte brut.

`LOG_LEVEL=warn` masque `info` et `success`, et `LOG_LEVEL=silent` masque
tout. La [page du logger](/essentials/logger/) dit le reste.

Ensuite, les réglages qui changent d'une machine à l'autre.
