Ce guide vous apprend **node-comfort**, de l'installation à un programme qui
tourne sur un serveur. Chaque étape vous dit **quoi faire** et **pourquoi**.

## Ce qu'est node-comfort

Presque tous les projets Node.js finissent par installer les mêmes outils : un
logger, dotenv, une bibliothèque de validation, un client HTTP, de quoi
réessayer, une bibliothèque de dates, une boîte à outils CLI. node-comfort les
réunit dans **un seul paquet sans dépendance**, construit uniquement sur ce que
Node.js fournit : `fetch`, `Intl`, `node:crypto`, `node:sqlite`.

```js
const nc = require("@ix-xs/node-comfort");

const config = nc.env.validate({ PORT: { type: "port", default: 3000 } });
const users = nc.readJSON("data/users.json", []);
nc.success(`Loaded ${users.length} users, port ${config.PORT}`);
```

| Pourquoi | Ce que cela change pour vous |
| --- | --- |
| Une dépendance au lieu de vingt | Une version à suivre, un journal des modifications à lire. Rien ne s'exécute à l'installation. |
| Une seule façon de faire | Les durées s'écrivent `"5m"` ou en millisecondes, les options viennent en dernier, les erreurs portent un `code` stable. |
| La documentation dans votre éditeur | Chaque fonction, option et type est décrit, en JavaScript comme en TypeScript. |
| Rapide à charger | Environ 4 ms. Chaque espace de noms se charge à sa première utilisation. |

| Espace de noms | Ce qu'il fait |
| --- | --- |
| [`logger`](/essentials/logger/) | Des logs avec niveaux, couleurs, sortie JSON et fichiers de log |

| [`env`](/essentials/env/) | Le chargement de `.env` et une configuration typée et vérifiée |
| [`checker`](/essentials/checker/) | Des vérifications de type qui servent aussi de gardes de type TypeScript |
| [`schema`](/data/schema/) | La validation, avec le type TypeScript déduit pour vous |
| [`str`](/data/str/), [`num`](/data/num/), [`arr`](/data/arr/), [`obj`](/data/obj/) | Les utilitaires de tous les jours pour les chaînes, nombres, tableaux et objets |
| [`time`](/data/time/) | Les dates dans toutes les langues et tous les fuseaux, les durées, les tâches planifiées |
| [`id`](/data/id/), [`crypto`](/system/crypto/) | Identifiants, jetons, hachage de mots de passe, chiffrement, JWT, codes 2FA |

## Ce qu'il faut savoir avant

- **Les bases de JavaScript** : les fonctions, les objets, `require`, `async`
  et `await`.
- **Ouvrir un terminal** dans un dossier et y taper une commande.

TypeScript n'est pas nécessaire. Le guide utilise CommonJS, le format par
défaut de Node.js ; [Installation](/start/installation/#commonjs-es-modules-and-typescript)
montre le même code en modules ES et en TypeScript.

## Comment lire ce guide

- Un bloc de code avec un **nom de fichier** est un fichier à créer, ou à
  remplacer, à cet endroit du projet. Les lignes surlignées sont les nouvelles.
- Un terminal montre ce qu'affiche le code de la page. Il a été exécuté à la
  construction de ce site : la sortie est réelle. **Rejouer** relance la scène.
- **Suivant**, en bas de page, mène à l'étape suivante.
